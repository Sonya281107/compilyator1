# Отчёт о реализации компилятора Ryst

## 1. Описание проекта

В рамках семестрового проекта разработан учебный язык программирования **Ryst** и реализован его компилятор **ryc** на C++23.

Компилятор принимает исходный файл `.ryst`, выполняет полный pipeline компиляции и создаёт нативный исполняемый файл для Linux x86-64:

```
source.ryst
    ↓  Lexer          lexer.cppm
    ↓  Parser         parser.cppm
    ↓  Semantic       semantic.cppm
    ↓  Codegen        codegen.cppm
source.ryst.asm  →  nasm  →  .o  →  gcc  →  ELF executable
```

## 3. Архитектура компилятора

Компилятор разделён на четыре C++23-модуля (`export module …`), импортируемых последовательно.

### 3.1 Лексер (`lexer.cppm`)

Преобразует байтовый поток в вектор `Token`. Поддерживает:
- идентификаторы и ключевые слова (включая `interface`, `impl … : I`)
- целочисленные литералы в dec/hex/bin с суффиксами (`42i32`, `0xFFu8`, `0b1010`)
- вещественные литералы с суффиксами (`3.14f32`, `2.7f64`)
- строки, булевы значения, операторы, разделители
- позицию каждого токена для диагностики

### 3.2 Парсер (`parser.cppm`)

Рекурсивный спуск. Строит AST через централизованные контейнеры (B.3.7):

```cpp
struct Program {
    std::vector<ExprNode>  exprs;      // ExprId = uint32_t
    std::vector<StmtNode>  stmts;      // StmtId = uint32_t
    std::vector<DeclNode>  decl_pool;  // DeclId = uint32_t
    std::vector<TypeNode>  types;      // TypeId = uint32_t
    SemTypePool            semtypes;   // семантические типы
    // A.2.13:
    map<string, vector<string>>       interface_method_names;
    map<IfaceImplKey, vector<string>> iface_impls;
};
```

Узлы AST — `std::variant` (ExprNode, StmtNode, DeclNode, TypeNode). Поддерживаемые объявления: `FnDecl`, `StructDecl`, `ImplDecl`, `InterfaceDecl`, `TypeAliasDecl`, `NamespaceDecl`.

### 3.3 Семантический анализатор (`semantic.cppm`)

Два прохода:
1. **Регистрация** — все объявления (функции, структуры, интерфейсы, impl) регистрируются в глобальной области, что позволяет вызывать функцию до её определения.
2. **Анализ** — тела функций, выражения, проверка типов, разрешение перегрузки, аннотирование AST (`sem_type`, `frame_offset`, `resolved_fn`).

Ключевые структуры данных семантики:
- `Scope` — стек областей видимости, каждая хранит `fns`, `vars`, `structs`, `interfaces`
- `SemTypePool` — пул интернированных семантических типов (инвариант: одинаковые типы → один ID)

### 3.4 Кодогенератор (`codegen.cppm`)

Обходит annotated AST и эмитирует NASM x86-64. Основные подсистемы:
- **RegAllocator** — раскраска графа интерференций (B.3.6), регистры `r12–r15`
- **Gen::emit_fn** — пролог/эпилог, стековый кадр, сохранение регистров
- **Gen::emit_expr** — рекурсивная эмиссия выражений
- **Gen::emit_vtable_thunks / emit_vtable_call** — динамический диспатч (A.2.13)

## 4. Реализованные дополнительные задания

### A.1.1 — Числовые типы (уровень 1)

Реализованы типы `i8, i16, i32, i64, u8, u16, u32, u64, f32, f64`. Лексер разбирает суффиксы литералов (`42i32`, `255u8`, `3.14f32`), hex (`0xFF`) и binary (`0b1010`) формы.

### A.1.7 — Вывод типов (уровень 1)

- Переменная без аннотации типа получает тип инициализирующего выражения.
- Функция без `-> T` получает тип возврата, выведенный из `return`-операторов тела.

### A.1.8 — Неявные числовые расширения (уровень 1)

Иерархия расширений: `i8→…→i64`, `u8→…→u64`, целое→`f32`→`f64`. Работает в: объявлениях переменных, присваиваниях, аргументах функций, бинарных операциях, `return`. Кодогенератор эмитирует `cvtsi2sd` при переходе из целого в вещественный тип.

### A.2.8 — Перегрузка функций (уровень 2)

Несколько функций с одним именем и разными параметрами. Mangling: `fname__T1__T2__…`. Разрешение перегрузки: сначала точное совпадение типов, затем — с учётом неявных расширений.

### A.2.10 — Перегрузка операторов (уровень 2)

Операторы `+`, `-`, `*`, `/`, `%`, `==`, `!=`, `<`, `<=`, `>`, `>=` могут быть перегружены для структур через специальные методы (`__add__`, `__eq__`, и т.д.).

### A.2.12 — Видимость pub/priv (уровень 2)

Поля структур и методы `impl`-блоков могут иметь модификатор `pub` или `priv` (по умолчанию — `priv`). Семантический анализатор хранит `field_visibility` и `method_visibility` в `StructInfo` и при каждом обращении проверяет допустимость доступа.

### A.2.13 — Интерфейсы и динамический диспатч (уровень 2)

**Синтаксис:**
```ryst
interface Shape {
    fn area(self: i64) -> i64;
}
impl Rect : Shape {
    pub fn area(self: Rect) -> i64 { return self.w * self.h; }
}
let s: Shape = rect_var;  // fat pointer
print(s.area());           // vtable call
```

**Реализация:**

*Хранение:* Переменная интерфейсного типа занимает 16 байт на стеке:
- `[rbp + off]` — data_ptr (указатель на конкретный объект)
- `[rbp + off + 8]` — vtable_ptr (указатель на vtable)

*Vtable* — массив указателей на функции в секции `.rodata`:
```nasm
__vtable_Rect_Shape:
    dq __thunk_Rect_Shape_area
```

*Thunk* — обёртка, конвертирующая вызовную конвенцию:
```nasm
__thunk_Rect_Shape_area:
    mov r11, rdi         ; rdi = data_ptr
    mov rdi, [r11 + 0]  ; rdi = self.w
    mov rsi, [r11 + 8]  ; rsi = self.h
    jmp Rect__area__Rect
```

*Диспатч:*
```nasm
; s.area() — после аргументной подготовки emit_call:
; rdi = data_ptr
mov r10, [rbp - (off+8)]  ; vtable_ptr в r10
call [r10 + slot*8]
```

Пример из `examples/interfaces.ryst` верифицирован: Rect {4,5}.area()=20, Rect.perimeter()=18.

### B.3.6 — Распределение регистров (раскраска графа, уровень 3)

1. Сбор интервалов жизни переменных за один проход по AST.
2. Построение графа интерференций: ребро между двумя переменными, чьи интервалы пересекаются.
3. Жадная раскраска по убыванию степени вершин; палитра: `{r12, r13, r14, r15}`.
4. Переменные без цвета (spill) — на стек `[rbp − N]`.

### B.3.7 — Arena-style AST (уровень 3)

AST не использует владение указателями между узлами. Все узлы (выражения, операторы, объявления, типы) хранятся в `std::vector` внутри `Program`. Связи — числовые ID (`ExprId`, `StmtId`, `DeclId`, `TypeId` = `uint32_t`). Это даёт:
- предсказуемое расположение в памяти (cache-friendly)
- отсутствие рекурсивных деструкторов
- простое сериализация и обход

## 5. Задача из пула — DFS обход графа (`examples/dfs.ryst`)

Реализован итеративный обход в глубину (DFS) ориентированного графа из 7 вершин на языке Ryst. Граф задаётся матрицей смежности 7×7. Явный стек реализован через массив фиксированного размера.

```ryst
// Граф: 0→1, 0→2, 1→3, 1→4, 2→4, 2→5, 3→6, 4→6, 5→6
// DFS порядок: 0 1 3 6 4 2 5
```

Программа компилируется компилятором ryc и выдаёт корректный результат.

## 7. Известные ограничения

- Нет динамической памяти (heap-аллокации)
- Массивы фиксированного размера
- Строки поддерживаются ограниченно (только строковые литералы и input)
- Нет обобщённых типов (generics)
- Нет лямбда-выражений
- Backend только x86-64 / NASM / Linux
- Диагностика: одна ошибка — остановка компиляции
- Thunk-конвенция для vtable поддерживает только методы с параметром `self` (без дополнительных аргументов — расширяемо)

## 8. Заключение

Разработан учебный язык Ryst и компилятор ryc, реализующий полный pipeline от исходного кода до нативного исполняемого файла. Реализованы 9 дополнительных заданий трёх уровней сложности, в том числе нетривиальные задания B.3.6 (раскраска графа) и B.3.7 (arena AST), а также A.2.13 (интерфейсы с динамическим диспатчем через vtable).
